가격은 적정한가?

먼저 연구 배경입니다. 데이터는 세 가지 측면에서 자산으로 자리 잡고 있습니다. 산업적으로 국내 데이터산업 시장은 2021년부터 2025년 추정치까지 연평균 9.8% 성장하고 있습니다. 기술적으로는 인공지능 서비스의 성능이 모델 자체뿐 아니라 학습 데이터의 내용, 구조, 품질에 좌우됩니다. 제도적으로는 데이터산업법이 ‘데이터 자산’을 법적으로 정의하고 가치평가와 품질관리를 지원하는 기반을 마련했습니다. 이렇게 자산이 된 데이터는 거래소에서 ‘데이터 상품’이라는 거래 단위로 유통됩니다. 데이터 상품은 상품명, 판매자, 카테고리, 파일 형식, 크기, 상품 설명, 컬럼 목록 같은 메타데이터와 함께 제공되고, 본 연구는 이 데이터 상품을 분석 대상으로 삼았습니다. 문제는 데이터가 형태가 없고, 같은 데이터라도 제공 기간이나 범위, 구조에 따라 효용이 달라져 가격의 적정성을 일률적으로 판단하기 어렵다는 점입니다.

메타데이터는 세 유형으로 구분해 각각 다르게 처리했습니다. 판매자, 카테고리, 파일 형식, 크기, 조회수 같은 정형 메타데이터는 원-핫 인코딩과 단위 변환을, 상품명과 요약·상세 설명 같은 비정형 텍스트는 TF-IDF 벡터화를, 컬럼 정보는 스키마 매칭 후 표준 키 기반 TF-IDF로 변환했습니다. 오른쪽은 가격 분포의 특징입니다. 유료 상품만 보더라도 고가 상품 때문에 꼬리가 긴 분포이고, 여러 가격대에 상품이 몰려 있으며, 데이터 크기와 가격 사이에도 단조 증가 관계가 뚜렷하지 않습니다. 그래서 가격에 로그 1 플러스 가격 변환을 적용하고, 이 문제를 비선형 회귀 문제로 정의했습니다. 평가할 때는 다시 원 단위로 역변환해 실제 금액 오차로 비교했습니다.
03 스키마 매칭

가장 비슷한 이름 찾기가 아니라, ‘통합할지 · 새로 만들지’의 판단

탐색은 SLM이, 판단은 LLM이 맡도록 역할을 나눴습니다.

문자열 기반

✓ 표기가 일관된 환경에서 단순·빠름

✕ BASE_YYMM ↔ 기준년월 미탐지

✕ 이용금액_2024 ↔ _2020 오탐지

임베딩 기반

✓ 표현이 달라도 의미가 가까운 후보 탐색

✕ 짧은 약어·날짜 복합명은 문맥 부족

✕ 최종 선택·신규 생성 판단 불가

SLM + LLM (본 연구)

✓ SLM: 대량 컬럼을 Top-K로 빠르게 축소

✓ LLM: 후보의 의미 재평가 · 통합/신규 결정

✓ 사전이 점진적으로 확장

위험 1

잘못된 통합 → 다른 의미의 컬럼이 한 키로 묶여 상품 구조가 왜곡

위험 2

과도한 신규 생성 → 사전이 파편화되고 관리 비용 증가

이제 첫 번째 핵심인 스키마 매칭입니다. 기존 방법의 한계부터 말씀드리겠습니다. 문자열 기반 매칭은 BASE_YYMM과 기준년월처럼 표기가 다른 같은 의미를 놓치고, 이용금액_2024와 이용금액_2020처럼 겉모양만 비슷한 컬럼을 잘못 묶습니다. 임베딩 기반 매칭은 의미가 가까운 후보를 찾는 데는 유용하지만, 짧은 약어나 날짜가 섞인 컬럼명은 문맥이 부족하고, 무엇보다 후보 중 무엇을 고를지, 아니면 새 컬럼을 만들지를 판단하지 못합니다. 본 연구의 매칭 문제는 단순히 가장 비슷한 이름을 찾는 것이 아니라, 기존 표준 키에 통합할지 신규 키로 분리할지를 결정하는 문제입니다. 잘못 통합하면 상품 구조가 왜곡되고, 신규 생성이 과도하면 사전이 파편화됩니다. 그래서 탐색은 SLM이, 판단은 LLM이 맡도록 역할을 나눴습니다.
03 스키마 매칭

SLM-LLM 기반 스키마 매칭 프레임워크

새 컬럼이 들어올 때마다 사전이 갱신되는 확장형 지식베이스 구조입니다.

SLM · 1차 탐색기

대량 컬럼을 빠르게 Top-K로 좁혀 LLM 비용·시간을 줄임

LLM · 2차 교정기

후보의 의미를 비교해 통합 또는 신규 생성을 결정

사전 항목 예시
canonical: CustomerCount
aliases: [고객수, cstmr_cnt, cust_cnt, …]
definition: 고객 수를 나타내는 지표
needs_review: false · embedding: 384-d
프레임워크의 동작입니다. 예를 들어 BASE_YYMM이라는 새 컬럼이 들어오면, SLM이 이를 384차원 벡터로 임베딩하고, 표준 스키마 사전의 벡터들과 코사인 유사도를 계산해 상위 K개 후보를 뽑습니다. 이 후보는 최종 결과가 아니라 LLM의 입력입니다. LLM은 원천 컬럼과 각 후보의 의미를 비교해 둘 중 하나를 결정합니다. 의미가 같은 키가 있으면, 예컨대 YearMonth의 별칭으로 BASE_YYMM을 추가합니다. 적절한 키가 없으면 새 표준 키를 만들되, needs_review를 true로 표시해 사람이 나중에 검토할 수 있게 합니다. 사전이 갱신되면 임베딩도 다시 계산되어, 다음 컬럼은 최신 사전을 기준으로 매칭됩니다. 오른쪽 아래는 사전 항목의 예시로, CustomerCount라는 표준 키 아래 고객수, cust_cnt 같은 다양한 표현이 별칭으로 묶여 있습니다. 즉 SLM은 탐색의 효율을, LLM은 판단의 정확성을 맡고, 사전은 상품이 늘수록 확장되는 지식베이스로 동작합니다.

해석 주의

기준 매핑값(Ground Truth)과 초기 사전을 LLM으로 생성했으므로, 0.7946은 사람이 만든 정답 대비 절대 정확도가 아니라 LLM 기준값 대비 정합률입니다.

성능 평가 결과입니다. 1,519개 원천 컬럼을 대상으로 세 관점에서 평가했습니다. 왼쪽 SLM 후보 탐색은 Recall@1이 0.21, Recall@5가 0.40, MRR이 0.28입니다. SLM 혼자서는 최종 매칭을 확정하기 어렵다는 뜻이고, 그래서 후보를 좁히는 1차 탐색기로 위치시켰습니다. 오른쪽 막대는 SLM 1순위와 LLM 최종 선택을 기준값과 비교한 결과입니다. 전체의 59.3%에서 SLM 1순위는 틀렸지만 LLM이 바로잡았고, SLM이 맞았는데 LLM이 잘못 바꾼 경우는 1.2%에 불과했습니다. 둘 다 맞은 20.1%와 LLM이 교정한 59.3%를 합하면 프레임워크 전체 정확도 0.7946이 됩니다. 다만 분명히 말씀드릴 점은, 기준 매핑값 자체를 LLM으로 생성했기 때문에 이 수치는 사람이 만든 정답 대비 절대 정확도가 아니라 LLM 기준값 대비 정합률로 해석해야 한다는 것입니다. 이 부분은 한계에서 다시 다루겠습니다.

05 설명가능성

SHAP: 하나의 예측을 피처별 기여의 합으로 분해

모델이 로그 가격을 학습했으므로 SHAP 값도 로그 단위입니다.

f(x) = φ0 + Σ φi

φ0: 전체 데이터의 평균 로그 예측값 · φi: i번째 피처의 기여

φ > 0예측 가격을 높이는 방향
φ < 0예측 가격을 낮추는 방향
|φ|기여의 상대적 크기
원 단위 가격exp(φ0 + Σφi) − 1
Waterfall 개념도
SHAP +1.46 ≠ “146만 원 상승” → 로그 가격이 1.46 상승
이제 예측의 근거를 설명하는 SHAP 분석입니다. SHAP은 게임 이론의 섀플리 값을 이용해 하나의 예측값을 기준값과 피처별 기여의 합으로 분해합니다. 양수면 가격을 올리는 방향, 음수면 내리는 방향이고, 절댓값이 크면 영향이 큰 것입니다. 주의할 점은 모델이 로그 가격을 학습했기 때문에 SHAP 값도 로그 단위라는 것입니다. 예를 들어 어떤 피처의 SHAP 값이 1.46이라고 해서 146만 원을 올렸다는 뜻이 아니라, 로그 가격을 1.46만큼 올렸다는 뜻입니다. 원 단위 가격은 전체 합을 지수 역변환해서 얻습니다.

이 결과를 가치평가 관점에서 정리하면, 가격 예측 기여 요인을 네 가지 후보 요인으로 구조화할 수 있습니다. 판매자, 카테고리 같은 거래·주체 요인, 크기와 조회수 같은 물리·시장 요인, 기간과 지역 같은 시간·공간 요인, 표준 컬럼과 컬럼 수 같은 구조 요인입니다. 다만 판매자 요인은 시장 가격을 설명하지만 데이터 자체의 내재 가치와는 구분해야 합니다. 활용 측면에서 판매자는 가격을 올리는 수단이 아니라 상품 설명의 완결성을 점검하는 데, 구매자는 제시 가격과 예측 가격의 차이를 보고 품질이나 권리 관련 추가 자료를 요청하는 데, 거래소는 등록 단계에서 기간·지역·스키마 누락을 진단하는 데, 평가 전문가는 시장접근법의 보조 자료로 활용할 수 있습니다. 강조드리고 싶은 것은, 예측 가격은 가치평가액이 아니라 검토 가능한 참고 근거라는 점입니다.

Q. 정확도 0.7946을 믿을 수 있나?

기준값·초기 사전 모두 LLM 기반 → 정합률로 한정해 해석. 전문가 정답셋과 사전 구축에 쓰지 않은 신규 컬럼으로 일반화 평가 예정

Q. 스키마 기여가 1.7%인데 의미가 있나?

MAE·RMSE·R² 모두 일관 개선. 성능 주도보다 상품 간 구조 비교 가능성과 해석 가능한 구조 신호(기준년월·CityName) 확보가 핵심

Q. 판매자·담당자 피처는 편향 아닌가?

판매자 가격 정책·문서 패턴 학습 가능성을 인정. 내재 가치와 구분하고, 판매자 제외 민감도·신규 판매자 검증·텍스트 정제를 후속 과제로 제시

Q. 왜 Dense 임베딩이 더 낮았나?

TF-IDF는 기간·지역·업종 등 특정 용어의 출현을 그대로 보존, 임베딩은 문장 의미로 압축하며 구분력이 약화된 것으로 해석

Q. 1,985건 선정 기준은?

숫자형 price_num > 0원인 상품. ‘7,000,000원’ 같은 문자열 가격(217건, 주로 범위형)은 단일 금액으로 해석하기 어려워 제외 (문자열 변환 포함 시 2,202건)

Q. Ridge 로그 R² 0.93인데 왜 탈락?

로그 공간 설명력과 달리 역변환 시 고가 상품 오차가 확대되어 원 단위 MAE 575만 원 · RMSE 6,865만 원

질의응답용 부록입니다. 발표 시간에는 포함되지 않습니다. 특히 예상되는 질문은 LLM이 만든 기준값의 순환성, 표준 스키마의 작은 기여도, 판매자 피처의 편향 가능성입니다. 세 질문 모두 논문 7.3절 한계와 7.4절 향후 연구에서 다룬 내용과 연결해 답변하면 됩니다. 1,985건 질문이 나오면, 숫자형 가격만 집계했고 문자열로 기재된 가격 217건은 대부분 범위형이라 제외했다고 답변합니다.
